# C2: verified feedback for a better DLM + C1 draft

The active C2 method supplies physically verified supervision to the draft generator. It connects continuous geometric improvement to discrete parameter learning. Its contribution is the feedback construction and learning interface: original-condition matching, equivalent teacher registration, exact-token physical rechecking, and supervision on actual visible student states. The current result does not rely on a learned online critic or on editing an F output.

## Division of work

| Component | Available information | Operation in this recipe |
|---|---|---|
| Planner | Material conditions | Produces the Plan and original prompt, retained throughout feedback |
| DLM | Prompt and visible geometry | Predicts lattice and coordinate token scores and contextual hidden states |
| C1 | DLM scores/hidden states, actual lattice, visible coordinates | Builds and samples the current axis's periodic joint distribution |
| Frozen F and physical tools | Complete draft lattice, elements and coordinates | Produce continuous candidates and measured energy/force/stress/hull feedback during data preparation |
| C2 feedback construction | Same-Plan drafts, continuous candidates, exact-token measurements and actual construction traces | Supplies registered complete teachers and positive prefix supervision |
| Feedback learner | Reviewed teachers and prefix targets | Updates DLM LoRA; C1 parameters stay fixed in the evaluated recipe |

## From continuous candidates to usable discrete supervision

1. Retain the exact Plan/prompt, the original draft and its real C1 construction trace. Continuous F and authorized physical relaxation propose improved complete lattices and coordinates.
2. Quantize and decode each proposed teacher, then measure the resulting exact token geometry. Quality of an unquantized or relaxed parent is not automatically a certificate for its quantized descendant.
3. Register an equivalent complete teacher using integer-bin periodic translations and same-element site permutations. This reduces arbitrary token differences while preserving the teacher lattice and relative geometry. The registered token structure is physically rechecked.
4. For prefix supervision, keep the student's actual lattice and every visible coordinate fixed. The teacher proposes only missing coordinates. These new completions are physically evaluated again; incompatible or non-improving combinations do not become positive core supervision.
5. Learn complete registered geometries and verified targets at actual commit positions. Unknown outcomes are not negative examples. Supervision can use a known relative quality improvement without requiring SUN/MSUN first.

The core prefix weight is a monotone transform of the measured, same-condition `raw_utility` improvement. That utility combines raw force, stress and hull-relative energy proxies; it is not SUN. A completion's gain labels that complete proposed structure, not the isolated causal effect of one coordinate token. The current loss is typed-token reconstruction, not an exact C1 trajectory likelihood or DPO objective. See the [artifact contract and frozen recipe](../registered-feedback.md).

## How C2 changes C1's next construction

Let `theta` denote DLM parameters and `psi` the periodic C1 head. C1 combines unary scores from `theta` with periodic interaction potentials conditioned on the current hidden states and lattice. Feedback updates `theta` to `theta_plus`; subsequent drafts use `q(theta_plus, psi)` instead of `q(theta, psi)`. Both unary scores and the hidden-state inputs to C1 can change even when `psi` stays fixed.

Complete-teacher views include a lattice phase with future coordinates masked, followed by coordinate phases. Actual-prefix views train on the recorded student lattice and visible coordinates. These two data paths address different parts of construction. The original prompt is present in both training and generation; physical tools may assess a complete structure without reading its prompt, but teacher assignment and feedback learning retain the same condition.

At deployment, the updated DLM and C1 generate a raw draft using their own parameters. F may optionally refine that draft. Teacher retrieval, CHGNet labels and future F outcomes are not inputs to online generation. C1 readaptation and learned online selection are separate research variants and are not claimed as contributors to the current fixed-C1 result.

## Current evidence and evaluation

The [controlled seen-TRAIN study](../results/registered-feedback-train.md) supports a native raw stability-proxy gain at matched body temperature, with diversity and F800 tradeoffs. It does not establish unseen generalization or learned online verifier gains.

The reporting-data expansion will compare raw, F800 and F400 under the same fixed Plans and both model versions. Each model's F400 and F800 start from the same saved raw. Changing `diff_steps` also changes `time_start`, so fewer steps are a budget/schedule comparison; quality, failures, unknowns and measured inference time must be reported before claiming an efficiency gain. ## Historical C2 editor, retained for reproduction

The following paragraphs and `scripts/train.sh c2` / `scripts/sample.sh c2` commands describe the older post-F editor. They are separate from the active `python -m dlm_iclr.feedback` method above.

C2 receives the continuous F output and its token view. Fixed source geometry and the evolving proposal geometry condition the DLM's embeddings. Candidate actions open coordinate blocks; masked conditional filling proposes new token values. Continuous patching changes only fields whose tokens changed, preserving the remaining F geometry.

An independent value model compares each candidate to the same current structure:

$$\Delta v(c)=v(S,c)-v(S,S),\qquad J_0(c)=2\Delta v_{NS}(c)+\Delta v_{NMS}(c).$$

KEEP has exactly zero relative value. The default candidate budget is eight proposals and at most 80 logical DLM forwards. Local proposals can cover 1, 2, 4 or 8 sites; whole-coordinate and cell modes are also available.

Training consists of crystal reconstruction warm-up, physical feedback collection, supervised editor fitting, a small physical-teacher update and value fitting using the final editor's features. The light update mixes original targets with a finite-candidate reward-weighted teacher at fraction 0.25 and temperature 0.1. It runs for one epoch at LoRA LR `1e-6` after the eight-epoch editor stage.

One additional revision inspects up to three changed fields of a completed single-site candidate. The same DLM predicts each masked field using the completed surrounding context. A learned contact-risk model tilts the conditional probabilities:

$$q_\lambda(k)\propto p_\theta(k)\exp[-\lambda\widehat r(k)].$$

The tilt uses strength at most 2 with KL budget 0.1. A single revised candidate joins the current structure and the original winner. Selection subtracts relative predicted risk with weight 0.5. The reference profile uses minimum predicted risk reduction `0.18866579450426538`.

The default pipeline evaluates F first and preserves confirmed SUN structures. Other requests use C2's learned selection. Final physical results are evaluated after selection.

```bash
bash scripts/train.sh c2 --config configs/local.json
bash scripts/sample.sh c2 --config configs/local.json
```
